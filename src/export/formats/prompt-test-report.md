## 測試階段：完成後請附上回報

這份說明還在測試階段。完成後，請在回覆的最後附上下面這份回報，使用者會把它交給 BPL 的開發者，用來改進這份說明。

- 請如實回報：沒做到、失敗或不確定的地方也要寫出來。
- 不需要貼出專案的程式碼，用文字描述即可。
- 沒有內容的項目寫「無」。
- 請把整份回報放在一個 Markdown code block 裡，方便使用者整段複製。

回報格式：

### BPL 測試回報

1. **本次設定**：照抄「本次設定」中的 pattern 與 component 名稱。
2. **專案環境**：框架與建置工具、JS／TS、Tailwind 版本、CSS 的組織方式、design token 的形式，以及是否已經有 BPL 的程式碼。
3. **檔案變更**：新增與修改了哪些檔案，各自改了什麼。
4. **與說明不同的做法**：哪些地方沒有照說明做（例如改了 class 名稱、拿掉 `@layer`、調整了 CSS），以及原因。
5. **錯誤與重試**：遇到的錯誤、需要反覆嘗試的地方；build 錯誤請附上錯誤訊息原文。
6. **Design token 對接**：改接了哪些 token、列出了哪些候選；判斷時遇到的困難。
7. **詢問使用者的問題**：執行前或執行中問了使用者哪些問題。
8. **說明的問題**：說明中不清楚、互相矛盾或缺少的地方。
9. **修改建議**：具體建議這份說明應該怎麼改（可以直接寫出建議的文字）。
